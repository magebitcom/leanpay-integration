# Release Notes - Variant Promotions in Installment Badges

**Date:** October 13, 2026
**Version:** 0.18.0
**Type:** Bug Fix
**Ticket:** LMM-144, LMM-151

---

## Overview

A product-level Leanpay promotion set on a configurable product's variant (child simple product) was ignored by the installment badge. The badge always showed the parent product's promotion, or the category or global one, even though checkout already resolved the purchased variant's promotion since 0.16.0 (LMM-143). The badge could therefore advertise different terms than the customer got at checkout.

- **LMM-144** - the product page badge now shows the promotion of the selected variant
- **LMM-151** - listing badges (category, search, widgets) now show the promotion of the lowest-priced variant

In both cases the parent product's promotion resolution (product, then category, then global) is the fallback, so products without variant-level promotions are unaffected.

---

## Problem Statement

### 1. Product page (LMM-144)

The product page badge resolved the promotion from the product read from the registry, which on a configurable product is always the parent. Selecting a variant only changed the amount the badge was calculated for, never the promotion, so a variant with its own vendor product code still showed the parent's terms.

### 2. Listings (LMM-151)

Listing badges resolved the promotion from the configurable parent as well. A listing has no selected variant, so a rule was needed for which variant's promotion to advertise.

---

## What's Fixed

### Selected variant on the product page

- Each variant's badge is rendered with that variant's promotion and handed to the price box when the variant is selected, through both the swatch renderer and the dropdown (`configurable`) widget
- The badge falls back to the AJAX endpoint when the selected price has no pre-rendered badge. The request now sends the product and variant IDs, so the endpoint resolves the same promotion
- Pre-rendered badges and the AJAX cache are keyed by amount and variant, so two variants with the same price but different promotions no longer share a badge
- The installment template no longer reads the deprecated `Registry`. The product is passed to it by the view plugins
- Fixed a JavaScript error in the swatch renderer mixin when no option was selected

### Lowest-priced variant on listings

A configurable product on a listing shows the promotion of its lowest-priced enabled, in-stock variant. When several variants share the lowest price, the first one with a promotion wins. When none of them has one, the parent's promotion applies as before.

Variants are loaded for every configurable product on the listing at once, with one parent-to-variant query and one variant collection load, so the query count does not grow with the number of product cards.

---

## Technical Details

### Affected Components

- `Helper/Data.php` - added `getVariantPromoCode()` (product page) and `getListingPromoCode()` with a batched, per-request variant preload (listings)
- `Block/Installment/Pricing/Render/TemplatePriceBox.php` - resolves the promotion from the `product` and `variant` data instead of the registry
- `Block/Installment/Pricing/Render/DefaultPriceBox.php` - uses the listing resolver outside the product page
- `Plugin/Block/Product/View/Type/ConfigurablePlugin.php` - renders each variant's badge with that variant's promotion
- `Plugin/Block/Product/View/ViewPlugin.php` - passes the product to the installment template
- `Controller/Installment/Index.php` - accepts optional `product_id` and `variant_id` parameters
- `view/frontend/web/js/price-box-mixin.js`, `swatch-renderer-mixin.js` - prefer the selected variant's badge
- `view/frontend/web/js/configurable-mixin.js` - new mixin for dropdown-based configurable products
- `view/frontend/requirejs-config.js` - registers the new mixin

### Upgrade Notes

- No database changes and no configuration changes
- Run `bin/magento setup:di:compile` (the `Helper\Data` constructor has new dependencies) and redeploy static content for the JavaScript changes
- The Hyvä compatibility module needs version 0.3.0 or newer for the product page part of this release. Listing badges work on Hyvä with this module alone

---

## Compatibility

- Backward compatible
- No visual changes to the badge, only the promotion terms it shows
- Products without a variant-level promotion show the same badge as before
- Checkout behaviour unchanged
- Applies to all regions; not specific to any plugin locale

---

## Testing Recommendations

1. Configurable product where one variant has its own Leanpay vendor product code: selecting that variant shows its terms, other variants show the parent's terms
2. Same as 1 with variants of equal price: switching between them still swaps the terms
3. Dropdown-based configurable product (no swatches): same result as 1
4. Price that has no pre-rendered badge, for example after changing a custom option: the AJAX badge shows the selected variant's terms
5. Category page: a configurable product whose lowest-priced variant has a promotion shows that variant's terms on its card
6. Lowest-priced variant disabled or out of stock: the next lowest-priced salable variant is used
7. Configurable product without variant promotions, and simple products: badge unchanged on the product page and listings
8. Search results and CMS product widgets: same as 5
9. Checkout redirect for the variant from 1: the same financial product as shown on the badge
